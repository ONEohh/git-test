# 文档质量检查规范 (Quality Checklist)

## 4.1 三级检查体系

### 一级：完整性检查 (Completeness)
- [ ] 标题是否包含"水浒传"、"软件工程"、"祖国发展"等核心关键词？
- [ ] 摘要能否独立成篇？（不看正文是否完整）
- [ ] 每个提纲节点都有对应内容？（无悬空标题）
- [ ] 结论是否回应了摘要中提出的问题？
- [ ] 是否有具体的案例或数据支撑观点？

### 二级：一致性检查 (Consistency)
- [ ] 术语全文统一（如前文用"网络安全"，后文不能随意换表述）
- [ ] 数据前后一致（如前文说"三个应用场景"，后文枚举是否为3个）
- [ ] 时态统一（回忆过去用过去时，现状用现在时，规划用将来时）
- [ ] 人称统一（以第一人称"我"为主，禁止混用）
- [ ] 标点规范（中文正文用全角标点）

### 三级：有效性检查 (Effectiveness)
- [ ] 每章删除测试：删除该章是否损害整体理解？如否，则该章冗余
- [ ] 反向阅读测试：从结论倒推，论据是否足够支撑？
- [ ] 陌生人测试：假设读者是领域外人士，是否有概念未解释？
- [ ] 时间胶囊测试：三年后重读，是否仍能理解核心观点？
- [ ] 行动导向测试：读者读完后能采取什么具体行动？

## 4.2 读书心得特化检查项
- [ ] 原文引用占比：是否过度引用沦为摘抄？（引用不超过30%）
- [ ] 个人思考占比：感想是否依附于具体文本？（思考不少于40%）
- [ ] 专业结合度：软件工程内容是否自然融入，而非生硬拼接？
- [ ] 时代关联性：是否有效连接个人成长与祖国发展需求？

## 4.3 评分与迭代机制
- **基线分**：满分100，一级检查每项15分，二级每项10分，三级每项5分
- **通过标准**：≥85分可输出；70-85分需标注待改进项；<70分重写
- **迭代指令**：若未通过，使用"基于[具体检查项]的反馈，请修正[具体位置]，要求[具体标准]"

## 4.4 常见失败模式 (Anti-patterns)
| 模式名称 | 症状 | 修复策略 |
|---------|------|---------|
| 头重脚轻 | 背景写3页，结论2句话 | 强制结论区字数≥摘要区×2 |
| 概念通货膨胀 | 堆砌术语无实质内容 | 每个术语必须跟"也就是说..."的解释句 |
| 情感透支 | 形容词密度>20% | 将所有"非常/极其/深刻"替换为具体程度副词或数据 |
| 正确的废话 | "我们要努力学习" | 加入主语、时间、衡量标准："我计划每天阅读30分钟" |
| 逻辑跳跃 | "因为A，所以C"缺B | 强制补充中间环节，或使用"这意味着..."过渡 |
| 两张皮现象 | 文学分析与专业内容脱节 | 增加"桥梁段落"，明确建立两者关联 |
