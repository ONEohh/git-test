# 文档质量检查规范 (Quality Checklist)

## 4.1 三级检查体系

### 一级：完整性检查 (Completeness)
- [ ] 是否包含开场问候与自我介绍？
- [ ] 是否清晰介绍了项目背景与痛点？
- [ ] 是否阐述了核心技术方案？
- [ ] 是否展示了关键测试数据？
- [ ] 是否有明确的总结与展望？

### 二级：一致性检查 (Consistency)
- [ ] 术语全文统一（如"瞳心守护"、"眼底筛查"）
- [ ] 数据前后一致（如准确率94.28%）
- [ ] 时态统一（以现在时为主）
- [ ] 人称统一（以"我们"为主）
- [ ] 时间控制：总时长≤3分钟，各部分时长分配合理

### 三级：有效性检查 (Effectiveness)
- [ ] 听众测试：假设听众是领域外人士，是否能理解核心内容？
- [ ] 记忆点测试：是否有3个以上清晰的记忆点？
- [ ] 行动导向测试：听众听完后是否了解项目价值？
- [ ] 语速适配：文字是否适合200字/分钟的语速？

## 4.2 演讲稿特化检查项
- [ ] 字数控制：是否≤600字？
- [ ] 术语解释：专业术语是否有通俗解释？
- [ ] 数据可视化：关键数据是否突出？
- [ ] 情感温度：是否既有专业严谨又有热情？

## 4.3 评分与迭代机制
- **基线分**：满分100，一级检查每项15分，二级每项10分，三级每项5分
- **通过标准**：≥85分可输出；70-85分需标注待改进项；<70分重写

## 4.4 常见失败模式 (Anti-patterns)
| 模式名称 | 症状 | 修复策略 |
|---------|------|---------|
| 头重脚轻 | 背景讲太多，成果展示不足 | 强制成果部分字数≥背景部分 |
| 技术堆砌 | 过多技术细节，听众难以理解 | 每个术语必须跟通俗解释 |
| 数据淹没 | 数据太多，重点不突出 | 只保留3-5个核心数据 |
| 逻辑跳跃 | 段落间缺乏连接 | 增加过渡句 |
| 超时风险 | 内容过多，时间超3分钟 | 精简内容，突出重点 |
